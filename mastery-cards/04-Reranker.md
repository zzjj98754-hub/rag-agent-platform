# 04 · Reranker · 掌握卡（入口版）

定位：S 级；检索链路精排段，追问集中在 Bi/Cross-Encoder 差异与阈值。
关联：03 粗排、05 评测阈值扫描、08 外部 API 超时。

## 1. 知识树

```
Reranker
├── 为什么精排
│   └── 粗排召回 ≠ 精排相关：topK×6 候选需要精细打分
├── 两种编码器
│   ├── Bi-Encoder：query/doc 分开编码 → cosine，快但粗（召回用）
│   └── Cross-Encoder：拼接联合编码 → 精分，慢但准（精排用）
├── 本项目实现
│   ├── BgeReranker：BAAI/bge-reranker-v2-m3 @ SiliconFlow
│   ├── 只精排 ~18 条候选
│   └── 失败 → 降级用粗排结果
├── 门控
│   ├── RelevanceGate：BGE ≥ 0.35 → 正常 RAG；< 0.35 → 拒答
│   └── 不相关文档是幻觉的最大来源
└── 关联
    ├── 03 粗排候选、05 阈值扫描
    └── 08 外部调用超时（connect 5s / read 30s）
```

## 2. 核心流程（骨架）

```
query + 18 候选 → 逐条 (query, doc) 拼接 → Cross-Encoder 打分 → 降序取 topK
  ├─ 最高分 ≥ 0.35 → 正常 RAG 路径
  ├─ < 0.35 → 告知 LLM 未找到，不拼文档
  └─ 调用异常 → 直接返回粗排结果（降级）
终态：RAG 答案 / 拒答 / 粗排降级答案
```

## 3. 两分钟口述（骨架，第 3 步再展开）

- 结论：召回用 Bi-Encoder 快，精排用 Cross-Encoder 准，两阶段是成本 / 精度平衡。
- 原理：拼接后自注意力联合建模 query-doc 交互。
- 关键细节：只精排 18 条、失败降级、门控 0.35。
- 代价：外部 API 延迟、依赖 key 与额度。
- 钩子：阈值怎么定的？→ 评测集上扫描，不是拍脑袋。

## 4. 三个为什么（入口问题）

1. 为什么精排用 Cross-Encoder？ → 方向：联合编码精度高；代价是慢。
2. 为什么只精排 topK×6？ → 方向：成本平衡，全量精排没必要。
3. 为什么加 RelevanceGate？ → 方向：低相关文档进 prompt = 幻觉源。

判定：能画出 Bi/Cross 编码差异并解释各自适用阶段 → 掌握。

## 5. 项目应用（证据映射）

| 场景 | 方案 | 收益 | 代价 |
|---|---|---|---|
| 精排 | BgeReranker 拼接打分 | 排序质量提升 | 每次检索 1 次外部调用 |
| 降级 | 异常 → 粗排结果 | 不阻塞链路 | 精度临时下降 |
| 拒答 | RelevanceGate 0.35 / RRF 0.01 | 防幻觉 | 阈值需评测校准 |
