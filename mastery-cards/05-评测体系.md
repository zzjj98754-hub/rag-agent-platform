# 05 · 评测体系 · 掌握卡（入口版）

定位：S 级；体现工程能力，追问集中在「怎么证明有效 / 怎么防回退」。
关联：02 Hybrid 对比、04 阈值校准、CI 工程化。

## 1. 知识树

```
评测体系
├── 评测集
│   ├── 30 条标注查询（eval-dataset.json）
│   ├── 4 类型：factoid 11 / conceptual 15 / multi-hop 3 / pronoun 1
│   └── 标注：groundTruthDocPrefixes 按 chunk 前缀匹配
├── 检索指标
│   ├── Recall@K / Precision@K
│   ├── MRR（首个相关文档的排名倒数）
│   └── NDCG@K（位置加权）
├── 生成评测
│   └── RAGAS 风格：Faithfulness / Answer Relevance / Context Relevance（关键词近似）
├── 工程化
│   ├── 对比实验：BM25-only vs Hybrid
│   ├── CI 门禁：Recall@3 ≥ 0.5（当前 warn）
│   └── waitForIngestion() 防异步注入 race
└── 基线（2026-06-08，30 查询）
    ├── Recall@3：0.96 → 0.99
    ├── MRR：0.91 → 0.95
    └── 延迟：12ms → ~14s
```

## 2. 核心流程（骨架）

```
加载 30 条 → 逐条检索（topK=3）→ 按前缀判相关 → 算 4 指标 → 汇总 + 分类型
  ├─ 低于基线 → 告警（未来可升级为 CI 失败）
  └─ 输出 Markdown 报告
对比实验：同一批 query 分别跑 BM25-only / Hybrid → 表格对比 + 耗时
生成评测：答案 / 上下文 → 关键词重叠近似三指标
```

## 3. 两分钟口述（骨架，第 3 步再展开）

- 结论：30 条 4 类型标注集 + Recall@3 主指标，可回归、可对比。
- 原理：Recall 是检索质量上限；MRR / NDCG 看排序质量。
- 关键细节：前缀匹配、waitForIngestion、基线表。
- 数据：Recall@3 0.96→0.99、MRR 0.91→0.95、代价 12ms→14s。
- 钩子：NDCG@3 为什么能 >1？→ 标注粒度是文档前缀，相关 chunk 可能多个。

## 4. 三个为什么（入口问题）

1. 为什么用 Recall@3 主指标？ → 方向：topK=3 面向用户，召回是答案上限。
2. 为什么建标注集而不是人工看几个例子？ → 方向：可回归、可防回退、可对比。
3. 为什么 NDCG@3 会 >1？ → 方向：标注粒度（文档前缀） vs 实际相关 chunk 数。

判定：能解释每个指标含义 + 说明 topK=3 的业务含义 → 掌握。

## 5. 项目应用（证据映射）

| 场景 | 方案 | 收益 | 代价 |
|---|---|---|---|
| 效果证明 | compareBm25VsHybrid | 0.96→0.99 量化提升 | Reranker 延迟拉到 ~14s |
| 防回退 | 全量评测 + CI 门禁 | 改参数可回归 | 当前门禁只是 warn |
